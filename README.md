# Trading Dashboard

个人用多周期技术分析看板。**零第三方依赖**（Python 3.12 标准库 + 一个前端图表库），双击 `start.cmd` 就能用。

---

## 快速开始

```
双击 start.cmd          （或命令行 python server.py）
浏览器打开 http://127.0.0.1:19766
```

启动约 1 秒。首次会自动探测网络通道（直连失败则走 `127.0.0.1:7897` 代理），进程常驻。

---

## 它解决什么问题

你原本的需求是「**方便自己查看多周期形态、多种技术分析结果**」。市面上的看板要么周期切换麻烦，要么指标口径不透明，要么一个页面塞满你根本用不上的东西（费率套利、清算流、多空战场）。

这个看板只做三件事：

1. **一条 K 线** —— 顶栏 6 个常用周期秒切，右侧下拉可选全部 15 个（1m / 3m / 5m / 15m / 30m / 1h / 2h / 4h / 6h / 8h / 12h / 1d / 3d / 1w / 1M）
2. **一张共振表** —— 6 个标准周期 × 17 个指标，一屏看完方向是否一致
3. **一句结论** —— 加权打分 + 共振判定，告诉你现在该不该动手

### 事件时间轴

K 线上叠加**历史事件**：每个事件在对应 K 线处画一条竖虚线，顶部一个双层标签 —— **上排标题栏（按类型着色）+ 下排日期**。

- 不同事件类型不同颜色（减半金色 / ETF 绿色 / 技术升级紫色 / 风险事件红色 / 宏观蓝色 / 监管橙色）
- **日期在未来的事件自动按「预估」处理**：标签虚线边框、竖线点线、标题追加「（预估）」、日期追加「预计」，并贴到图表右缘
- 标签默认放在竖线右侧，靠右或与相邻标签重叠时自动翻到左侧，再不行就向下换行
- 随缩放平移实时重算位置
- K 线上方有「历史事件」勾选框，可一键开关；旁边是当前标的的事件类型图例
- 事件分类可逐个勾选，也可以用「**全开 / 全关**」一键切换（默认不含「行业」，否则日历里的几百条行业快讯会淹没图表）
- 点 K 线任意一根，弹窗列出**这根 K 线发生的全部事件与快讯**（含开高低收、涨跌幅）

**数据在 `data/events.json`，直接改这个文件即可**（保存后刷新页面生效）：

```json
{ "date": "2020-05-11", "title": "BTC 第三次减半",
  "brief": "区块奖励 12.5 → 6.25 BTC", "type": "halving", "scope": "BTC" }
```

| 字段 | 说明 |
|---|---|
| `date` | `YYYY-MM-DD`（UTC） |
| `title` | 标签标题 |
| `brief` | 一句话说明（可空） |
| `type` | 决定颜色，见文件里 `types` 段，可自定义新增 |
| `scope` | `BTC` / `ETH` / `all`（`all` 表示所有标的都显示） |
| `color` | 可选，覆盖该类型的默认颜色 |

已预置 18 条：四次减半、ETF 获批、Merge/Dencun/Pectra、LUNA 崩盘、FTX 破产、312 暴跌、硅谷银行、美联储降息等。

> 历史事件没有可靠的免费 API，所以用人工维护的 JSON —— 与其自动抓一堆不准的，不如你自己维护一份准的。

**看长周期才能看到老事件**：周线会载入 700 根（约 13 年），日线 500 根。1h 只有 320 根（约 13 天），2020 年的事件自然落在范围外，不会画出来。

### 多空损（预估清算）

右栏「多空损」面板 + K 线上的两条虚线，标出**最近的多头爆仓区（绿）和空头爆仓区（红）**。

这是**估算模型**，原理在 `core/liqmap.py`：

```
持仓量 OI × 多空比例  →  多头/空头名义持仓
最近 300 根成交量加权收盘价  →  开仓价分布
杠杆分布 5/10/20/25/50/100 倍  →  每笔的爆仓价
爆仓价分箱累加  →  每个价位的「多损 / 空损」美元金额
```

关键约束：**只统计还没被扫掉的仓位** —— 多头爆仓价必须低于现价，空头必须高于现价，否则等于把历史爆仓算到未来。

模型局限：
- 杠杆分布是假设的常数，不是真实数据
- 开仓价用成交量加权近似，不知道真实成交价
- 维持保证金率统一取 0.4%

所以它是**风险区位参考**，不是精确的强平清单。原站同类功能也标注为模型估算。

## 常用调整

全部在 `core/config.py`：

```python
SYMBOLS   = ["BTC", "ETH", "SOL", "BNB", "XRP", "DOGE"]   # 想加什么加什么
TIMEFRAMES = {"15m":900, "30m":1800, "1h":3600, "4h":14400, "1d":86400, "1w":604800}
```

## 回测校准：这套打分靠谱吗

点右栏「回测校准」，用 125 天历史验证。**结论不好看，但很重要**：

| 问题 | 结果 |
|---|---|
| 共振分能预测涨跌吗 | 很弱（IC **+0.030**，\|IC\|>0.05 才算有用） |
| 多周期聚合比单周期强吗 | **没有**（+0.030 vs −0.026，差异在噪声内） |
| 哪个分数段真有用 | 只有 **+30~+50**（按方向期望 **+0.63%**） |
| 极端分数 | **要反着看**（>+50 做多平均亏 0.39%，胜率仅 36%） |
| 哪个周期最有信息 | **日线 IC +0.163**；**周线 −0.054（权重却最高）** |

**三个可直接改变用法的结论：**

1. 它是个**多头择时器**，不是对称多空信号 —— 负分区间做空的期望全为负。
2. **分数 > +50 是衰竭区**，不是加速区，追高风险大。
3. 权重最高的周线恰恰最没用，日线才是主力。

⚠️ **另一个教训**：第一次用 15 天数据回测，IC 是 **−0.27**（看起来「必须反着做」）。拉到 125 天后变成 +0.03。短样本的结论完全是行情噪声。

完整分析、方法、踩坑过程见 [docs/03-回测报告.md](docs/03-回测报告.md)。

## 生成研判（一键分析）

顶栏「**生成研判**」按钮 → 自动汇总当前标的的全部数据，生成一份完整的技术分析。

**不是套模板**，每一段结论都由数据条件触发：

| 章节 | 内容 | 生成方式 |
|---|---|---|
| 结论 | 一句话定性 + 4 张关键卡片 | 由加权分、同向周期、多空比、清算比拼出 |
| 事实层 | 13 项原始读数 | 交易所数据直出 |
| 多周期结构 | 6 周期得分 / 判定 / 权重 / 加权贡献 / 主要依据 | 逐周期明细 |
| 关键价位 | 1h/4h/1d 的支撑阻力、POC/VAH/VAL、枢轴、ADX/RSI、云层 | 各周期独立计算 |
| 多空损 | 最近爆仓区 + 3% 内累计 | 模型估算 |
| **矛盾与辨析** | **8~10 条分析**（见下） | **规则触发** |
| 观察清单 | 会强化 / 会削弱当前判断的条件 | 由最近的支撑阻力、清算带、情绪指标推导 |
| 可靠性边界 | 5 个环节的可信度分层 | 固定说明 |

### 「矛盾与辨析」的触发规则

每条规则独立判断，命中才输出：

| 触发条件 | 输出 |
|---|---|
| 周线方向与加权方向相反 | 周线与整体方向冲突 |
| 任一周期 \|分数\| ≥ 70 | 极端分数：统计可靠性下降 |
| 日线 RSI < 32 且 ADX > 20 | 日线超卖，但趋势未止 |
| 价格低于 1h VAL > 1% | 价格已跌出 1h 价值区 |
| 全网多空比 > 2.5 | 多头拥挤 |
| 3% 内多损/空损 ≥ 3 | 下方清算燃料远多于上方 |
| 量比 < 0.6 | 当前缩量 |
| 1h TTM 挤压开启 | 处于波动率压缩 |
| taker 比与 CVD 方向相反 | 两项资金指标口径冲突 |
| 1h 与 4h 结构标签不同 | 局部与全局结构不一致 |

**同一天不同标的，生成的条目完全不同**（实测：BTC 8 条、ETH 9 条、1000PEPE 6 条）。

## 接入 AI（可选）

**不配置也能用全部功能。** 研判本身是规则引擎生成的，AI 只是上面加的一层「叙述 + 追问」。

配置方式（环境变量优先，改完重启服务）：

```bat
set TD_AI_KEY=sk-xxxxxxxx
set TD_AI_BASE=https://api.deepseek.com/v1     :: 可选
set TD_AI_MODEL=deepseek-chat                  :: 可选
```

任何 **OpenAI 兼容** 接口都能用，内置 7 个预设（改 `TD_AI_BASE`/`TD_AI_MODEL` 即可切换）：

| 预设 | BASE_URL | 默认模型 |
|---|---|---|
| deepseek | `https://api.deepseek.com/v1` | deepseek-chat |
| zhipu | `https://open.bigmodel.cn/api/paas/v4` | glm-4-flash |
| moonshot | `https://api.moonshot.cn/v1` | moonshot-v1-8k |
| dashscope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen-plus |
| openai | `https://api.openai.com/v1` | gpt-4o-mini |
| ollama | `http://127.0.0.1:11434/v1` | qwen2.5:7b（本地免费） |
| siliconflow | `https://api.siliconflow.cn/v1` | Qwen/Qwen2.5-7B-Instruct |

> 走本地 Ollama 的话连 Key 都不需要，但 `stream_chat` 要求 Key 非空，填任意字符串即可。

### 怎么用

研判弹窗底部有「**AI 解读**」区：

- **解读** —— 把整份研判 JSON 交给模型，生成 500 字以内的叙述
- **追问** —— 输入框里问「周线为什么和整体方向冲突？」，模型基于同一份数据回答
- 流式输出，逐字显示
- 未配置时按钮置灰，并提示如何配置

### 防幻觉设计

| 措施 | 说明 |
|---|---|
| **只喂算好的数据** | 模型拿不到原始行情，无法自行取数或推算 |
| **提示词硬约束** | 禁止引入外部数据、禁止编造数字、禁止给点位、数据不足必须说「数据不足」 |
| **数值核对** | 输出后用正则抽取所有数字，与原始 JSON 比对，**数据里没有的数会被标红提示** |
| **明确分层** | 规则引擎负责结论，AI 只负责措辞，AI 说的不算数 |

数值核对支持负号与 K/M/B/% 单位换算，不会把 `-46` 误判成 `46`，也不会把 `1.21B` 误判成 `1.21`。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 顶部显示「数据快照」 | 网络断了，正在用落盘数据 | 检查代理是否启动 |
| 通道显示「直连」但没数据 | 探测时直连恰好通，之后被墙 | 重启服务，或把 `PROXY` 设为代理地址 |
| 端口被占用 | Windows 保留端口段 | 改 `config.py` 的 `PORT`，避开 8725–8824 |
| 中文乱码（控制台） | 终端编码 | `set PYTHONIOENCODING=utf-8` |
