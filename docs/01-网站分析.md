## 1. 站点概况

一个**加密货币多交易所清算 / 盘口 / 衍生品聚合看板**，带会员登录、AI 分析、以及两个游戏化的「多空战场」页面。

- 对外叙事：`12所 · 现货+永续 · 全网量能 · 实时清算`
- 实际形态：单页应用（无框架、原生 JS），Python 后端反代/直服静态文件
- 商业闭环：广告位（`/api/ads` 写死了 QQ/微信/TG 引流）→ 注册 → 免费/会员分级 → AI 分析（消耗大模型额度）→ 引流到 `1coin.vip` 卖指标/返佣

## 2. 技术栈推断

| 层 | 判断 | 依据 |
|---|---|---|
| HTTP 服务 | Python 3.9.21 `http.server` 手写路由 | `Server: BaseHTTP/0.6 Python/3.9.21`；`404 {"error":"not found"}`；`OPTIONS` 返回 501 |
| 并发 | 多线程（`ThreadingHTTPServer`） | 18 秒的 `/api/book` 期间其他端点仍可响应 |
| 存储 | SQLite（推测） | 用户 `created_at`、`signals.id` 递增到 699、`battle` 轮次持久化 |
| 实时下行 | SSE（`text/event-stream`） | `/api/liq_stream`，非 WebSocket |
| 上行采集 | 12 所 WebSocket + REST 轮询（服务端进程内） | `/api/status.liq` 逐所连接状态 |
| 前端 | 原生 JS + `lightweight-charts` 4.1.3 + 自研 canvas | 无 React/Vue，无构建产物，全部未压缩 |
| 鉴权 | `Bearer` token 存 `localStorage` | `authHeaders()` → `Authorization: Bearer ...` |
| 推送 | Web Push + VAPID | `/api/push/pubkey` 返回 `BKq7Vbmv...` 公钥 |
| 部署 | 无 CDN、无 Nginx 特征、`Cache-Control: no-store` | 直连 8090 端口 |

## 3. 功能地图

### 3.1 主看板 `/`（三栏布局）

**左栏 · AI 分析**
- 3 个模式入口：日内 / 波段 / 长线

## 6. 鉴权与安全评估

### 6.1 设计
- `POST /api/auth/login` → `{token, level, is_admin}` → 存 `localStorage.user`
- 受保护端点读 `Authorization: Bearer <token>`
- 前端 `loginGate` 只是一个 `display:none` 的遮罩：`showDashboard()` 直接把 `appMain` 显示出来，**不做任何服务端会话校验**

### 6.2 问题清单

| 等级 | 问题 | 后果 |
|---|---|---|
| 🔴 高 | 清算/盘口/K 线/信号/新闻等 **19 个端点完全无鉴权** | 任何人写 3 行脚本即可白嫖全部数据，会员体系失效 |
| 🔴 高 | 登录门纯前端 | 开发者工具删掉 `display:none` 即可进主界面（但 AI 仍需真 token） |
| 🟠 中 | token 存 `localStorage`，无 HttpOnly / 无过期字段 | 任意 XSS 即可窃取；token 疑似永久有效 |
| 🟠 中 | `/api/status` 返回 `web_dir: "C:\\Users\\Administrator\\Desktop\\v6\\web"` | 泄露操作系统、用户名、部署路径，为后续攻击提供情报 |
| 🟠 中 | `Server: BaseHTTP/0.6 Python/3.9.21` | Python 3.9 已 EOL，版本号直接暴露 |
| 🟠 中 | 无任何安全响应头（CSP / X-Frame-Options / X-Content-Type-Options / HSTS） | 点击劫持、MIME 嗅探、XSS 缓解手段为零 |
| 🟡 低 | 注册开放且无验证码、错误统一 HTTP 200 | 可批量注册，消耗 AI 额度 |
| 🟡 低 | `/api/ai` 全局单任务锁（429） | 一个用户发起分析 = 全站其他人排队 2–3 分钟 |
| 🟡 低 | 无速率限制 | `/api/book` 18 秒的请求可被无限并发触发 → 低成本 DoS |
| ✅ 良好 | `/api/admin/*` 服务端校验 `is_admin`，无 token 与假 token 均 403 | 后台确实受保护 |
| ✅ 良好 | `/api/ai`、`/api/prefs`、`/api/push/subscribe` 有服务端鉴权 | |

## 7. 数据质量缺陷（这些会直接污染指标）

| # | 现象 | 证据 | 影响 |
|---|---|---|---|
| 1 | 时间戳混用秒/毫秒，出现**负年龄** | `exchanges[binance].futures.age_ms = -10,284,269,174,921`；`wall_lifecycle.active[].age_s = -10,142,729,607` | 墙的「存活时长 / 被吃穿 / 撤单」判定全部不可信 |
| 2 | Binance **现货价冻结** | `spot.last = 75845.0`，同期合约 `futures.last = 73932.7`（现货比合约高 2.6%） | Coinbase 溢价、盘口失衡、现货量能、跨所价差被污染 |
| 3 | `delta` 指标把**成交量当买卖差** | `indicators.delta.delta[0] === klines[0][5]`（10946.028） | 订单流 Delta 无意义 |
| 4 | 山寨清算雷达全 0 | `/api/radar` → `alt_24h_usd: 0, ratio: null, surges: []` | 该功能实际未跑通 |
| 5 | KOL 观点**停更 3 个月** | KOL 条目时间 `08-16 20:51`，新闻是 `11-11 20:21` | nitter 抓取早已失效 |
| 6 | ETF 流向最新值为 0 | `macro.etf.latest.total_musd: 0.0` | 当日数据未更新，图上是断点 |
| 7 | `step` 参数被忽略 | `/api/battle?step=0.5` 与 `step=100` 返回同样的 `step: 1000.0` | 前端切换无效 |
| 8 | `age_ms` 字段定义为「距上次更新的毫秒数」，却与 0 比较 | 见 #1 | 探活逻辑失效 |
| 9 | 恐贪指数时间戳为字符串 | `fear_greed.timestamp: "1794355200"` | 类型不一致，前端要额外转换 |

## 8. 值得借鉴 vs 必须重做

### ✅ 值得借鉴（这是这个产品真正的资产）

1. **指标计算放服务端**，前端只渲染 —— 保证 12 所、6 周期、4 币种的结果一致，且便于 AI 直接消费同一份结构化输入。
2. **统一「最新值扁平对象」**（`indicators.last` 的 47 个标量）—— AI Prompt 和数据面板共用，避免重复计算。
3. **聚合盘口模型**：按 `spot` / `fut` 拆分量、按 `interval` 分档、`cum` 累计、`bid_wall`/`ask_wall` 标注 —— 数据结构设计得相当干净。
4. **清算地图用 OI + 杠杆分布反推**（`model: "oi_leverage_v2"`, `funding_bias`）—— 在拿不到真实强平价时这是合理近似。
5. **挂单墙生命周期**（`active` / `recent_gone` / `consumed` / `pulled` / `replenish`）—— 「真墙 vs 假墙」的思路是对的，只是时间戳算错了。
6. **战场游戏化**：把价格区间变成 8 小时防守战，把「看盘」变成「有胜负记录的游戏」——留存设计很巧妙。
7. **SSE 而非 WebSocket**：单向广播场景下更简单、更好穿透代理。

### ❌ 必须重做

1. **鉴权**：改为服务端会话（HttpOnly Cookie 或短时 JWT + 刷新），登录门不能只是 CSS 遮罩。
2. **传输**：`/api/klines` 必须支持 `limit` + 增量（`since`）；必须 gzip/br；必须 ETag。
3. **推送**：SSE 改增量（只推变化的价格、新增清算），82 KB → 目标 < 2 KB/帧。
4. **指标计算**：按 `(symbol, tf)` 缓存 + 只算新增的一根 bar，不要每次重算 1006 根。
5. **状态语义**：`connected` 必须表示「最近 N 秒收到过数据」，而不是「TCP 连上了」。
6. **时间戳**：全链路统一毫秒，服务端下发 `server_ts` 供前端校准。
7. **错误语义**：HTTP 状态码要正确（注册失败不应该是 200）。

## 9. 对这个「工具」的启示

如果你要做的工具是**同类产品**（多所清算/盘口聚合看板），这个站点给出了完整的需求清单，但实现方式几乎全部要换掉。

如果你要做的工具是**消费这个站点的数据**（采集器 / 监控 / 二次分析），那么：

- **好消息**：19 个核心数据端点无鉴权，直接 `GET` 即可，不需要账号。
- **坏消息**：数据本身有第 7 节的 9 类缺陷，尤其是**现货价冻结**和**负时间戳**，直接用会得出错误结论，需要自己做清洗和交叉校验。
- **注意**：`/api/ai` 和 `/api/prefs` 需要 token；`/api/book?interval=0.5` 单次 2.9 MB、18 秒，不适合高频采集。
